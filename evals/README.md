# Quome plugin evals

Cases for `claude plugin eval`, checking that the `playbook` tool and the
generated `quome` skills work end to end.

**Run these by hand, as yourself, against a test org you are connected to
(`quome connect`). Never against a production org.** The cases call the real
`quome mcp` server in your Quome Cloud org, so they use your credentials and
may read org state. They do not ask the agent to carry out any playbook step.

## Running

```sh
scripts/run-evals.sh --profile test-org                  # the playbook-* cases (work today)
scripts/run-evals.sh --profile test-org --after-listing  # the skill-* cases (see below)
scripts/run-evals.sh --dry-run        # build + validate the scratch plugin, run nothing
scripts/run-evals.sh -- --case 'playbook-git'   # extra flags go after --
```

`claude plugin eval` needs the evals inside a plugin directory, but the `quome`
plugin is generated by `quome skills sync`. The script therefore builds a scratch
plugin (a `quome` manifest, a `.mcp.json` for the real `quome mcp` server, and a
copy of this directory), validates it, shows the profile and org you are about to use (and asks you to confirm), and runs the eval against it. Every flag
choice is explained in the script. `--from-installed` starts from a read-only
copy of your synced plugin instead of the bare manifest.

A real run requires `--profile`; only `mcp__plugin_quome_quome__playbook` (and `Skill` for the skill cases) is granted, so the agent cannot act on the org.

Reports go to `target/evals-report.html` and `target/evals-results/`.

## Cases

- `playbook-<name>`: one for each of the 28 playbooks. The prompt asks Claude to
  fetch the playbook by name with the `playbook` tool and report its first
  step. Graders check the tool was called with that name and that the answer
  reflects the rendered steps. These work while the playbooks are unlisted.
- `after-listing/skill-<name>`: one for each of the 17 specific playbooks. A
  natural request ("add Google sign-in to my recipes app") whose graders check
  that the `quome:<name>` skill fired and `playbook` was called. **These need the
  playbook to be listed on the server and `quome skills sync` to have written
  its skill first**; until then they fail by design. The `skill-fired` grader is
  `with-only`, so it is shown as a plugin-fired indicator rather than scored in
  the baseline comparison.

General playbooks (`sandboxes`, `apps`, `auth`, `email`, `caches`, `git`, `credentials`) take a
required `what`; the cases pass one.
